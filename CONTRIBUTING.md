# Contributing to the commons

Everyone's welcome — developers, researchers, economists, founders, skeptics. You don't need to write code to contribute; the highest-value thing you can do is **poke holes**.

## Ways to take part

- **Ask or answer** in **Discussions → Q&A** (questions get marked with an accepted answer).
- **Propose** in **Discussions → Ideas / RFC** — a design, a critique, a mechanism-design concern, a "have you considered…". Big protocol changes start here as an RFC before any code.
- **Show & Tell** — built something with the trust layer? Share it.
- **File issues / PRs** on the individual code repos ([`repid-engine`](https://github.com/DealAppSeo/repid-engine), [`hyperdag-protocol`](https://github.com/DealAppSeo/hyperdag-protocol), [`trustshell`](https://github.com/DealAppSeo/trustshell)). This repo is for conversation; the code lives there.

## How we work (the ethos)

The project's method *is* its thesis — so we hold the community to it too:

- **Evidence over claims.** A number without its source, corpus size, and confidence interval is an opinion. Bring receipts.
- **Honesty over hype.** We publish our recall *and* our precision, our failures *and* our wins. Refuting a premise is more valuable than confirming one.
- **Kindness with candor.** Push back on ideas hard; on people, never.
- **Reward truth-seeking.** The best contribution is the one that overturns a wrong assumption — ours included.

## Good first contributions

- Try `hal verify "<some claim>"` (CLI) and report anything surprising in Q&A.
- Red-team a claim in a spec or the eval — where does it not hold?
- Improve a README or a definition (clarity is a real contribution).

By participating you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).
